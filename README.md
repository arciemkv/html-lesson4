# Практическое занятие №4: Структурирование документов с помощью таблиц

---

## 👥 Инструкция по Scrum-взаимодействию в командах

Разработка выполняется в микро-группах по 2–3 человека. Команда должна распределить роли:
1. **Team Lead (Git Master):** Создает форк репозитория, добавляет коллег в Collaborators, следит за чистотой веток и отправляет финальный Pull Request.
2. **Frontend Developers:** Разрабатывают изолированные HTML-страницы и проектируют таблицы по ТЗ.

### ⚠️ ВАЖНОЕ правило изоляции (Защита от затирания файлов)
Чтобы избежать конфликтов слияния (Merge Conflicts), каждая команда работает строго внутри своей уникальной директории в корне репозитория! 
* Название папки: `team-[фамилия1]-[фамилия2]-[фамилия3]` (например, `team-mamchits-kuznetsov/`).
* Внутри этой папки создаются только `.html` файлы страниц.
* Исходные файлы в корне репозитория (`new shablon.html` и `shablon.html`) изменять и перезаписывать **категорически запрещено**! Используйте их как чистый каркас, скопировав в свою папку.

## 🛠️ Техническое задание (Строго на чистом HTML)

Используя текст из файла `Planeta_text.doc`, базовую разметку из шаблонов и графические ресурсы из папки `Images`, постройте многостраничный справочный портал **«Удивительная планета»**.

### 🟢 Уровень BASE (Обязательный минимум)
1. Внутри командной папки создать файл `index.html`.
2. Сверстать таблицу «Самые большие (по площади) государства».
3. **Требование к семантике:** Таблица должна содержать элементы `<table>`, `<caption>`, `<thead>`, `<tbody>`, `<tr>`, `<th>`, `<td>`.
4. **HTML-оформление:** Так как каскадные таблицы стилей (CSS) мы еще не проходили, для визуального отображения сетки используйте стандартные атрибуты тега `<table>`:
   * `border="1"` или `border="5"` (задание толщины рамки);
   * `cellpadding="4"` (внутренние отступы в ячейках);
   * `cellspacing="0"` или `cellspacing="4"` (расстояние между ячейками);
   * `bgcolor="..."` (цвет фона для выделения шапки или строк).

### 🔵 Уровень JUNIOR (Многостраничность и Вертикальное слияние)
1. Выполнить все требования уровня **BASE**.
2. **Архитектура:** Развернуть 3 полноценные страницы: `index.html` (Главная), `geography.html` (География) и `animals.html` (Животные).
3. **Навигация:** На всех страницах настроить сквозное меню для беспрепятственного перехода по сайту с помощью гиперссылок тега `<a>`.
4. **Вертикальное слияние (`rowspan`):** На странице `animals.html` реализовать таблицу «Самые прыгучие наземные животные». Сгруппировать категории «Прыжок в длину» и «Прыжок в высоту» с помощью атрибута `rowspan` в тегах `<td>`/`<th>`.
5. **Графика:** Встроить изображения из папки `Images`. Для каждого тега `<img>` обязательно указать заполненный `alt`, а также физические параметры `width` и `height` в пикселях.
6. **Anti-AI контроль:** Возле каждого тега с `rowspan` написать краткий ручной комментарий, поясняющий логику расчета (например: `<!-- rowspan="2", так как объединяем 2 строки прыжков в длину -->`).

### 🔴 Уровень PRO (Сложные таблицы, Карты рамок и Горизонтальное слияние)
1. Выполнить все требования уровней **BASE** и **JUNIOR**.
2. **Максимальный контент:** Добавить страницы `plants.html` (Растения) и `sources.html` (Информационные источники). Перенести абсолютно все данные из файла `Planeta_text.doc`.
3. **Горизонтальное слияние (`colspan`):** Спроектировать таблицы на страницах растений/источников с объединением заголовков групп по горизонтали с помощью атрибута `colspan`.
4. **Управление сеткой таблицы (`rules`):** На странице источников применить к таблицам атрибут `rules="cols"` или `rules="rows"` совместно с `frame="..."` для демонстрации управления отображением внутренних и внешних границ без использования CSS.
5. **Юзабилити:** Реализовать локальные якорные меню на длинных страницах для быстрого перехода к нужным таблицам и ссылки «ВВЕРХ» под таблицами для возврата к шапке.

## 📉 Критерии автоматического снижения баллов (Чек-лист штрафов)

*   **⚠️ Сдача работы вне командной папки (до -3 баллов):** Если файлы вашей команды лежат непосредственно в корне репозитория или изменены шаблоны `new shablon.html` / `shablon.html`.
*   **⚠️ Работа велась в ветке `main` вашего форка (до -2 баллов):** Разработка должна происходить строго в ветке `homework-04`.
*   **❌ Нарушение геометрии сетки таблицы (до -2 баллов):** Если при использовании `rowspan` или `colspan` таблица «расползается», а количество ячеек в строках не совпадает.
*   **❌ Ошибки W3C Валидатора (до -2 баллов):** За любые критические ошибки (Errors), обнаруженные при валидации HTML-кода.
*   **🤖 Отсутствие ручных комментариев к rowspan/colspan (до -2 баллов):** Возле каждого тега со сложным объединением строк или столбцов должен быть оставлен короткий комментарий с логикой расчета.

## 📦 Алгоритм отправки работы на проверку

1. **Тимлид** делает Fork репозитория `fufaev/html-lesson4`.
2. Команда клонирует форк локально и создает ветку `homework-04`: `git checkout -b homework-04`.
3. Перед началом работы каждый участник вводит команду `git pull origin homework-04`.
4. По завершении разработки Тимлид отправляет **один Pull Request** из ветки `homework-04` своего форка в ветку `main` оригинального репозитория.

## 👥 Git-инструкция для Team Lead (Как не сломать репозиторий)

Так как вы работаете в команде, несколько человек будут отправлять код в один и тот же форк. Чтобы избежать конфликтов, Тимлид должен координировать процесс.

### Шаг 1. Первичная настройка (Делает ТОЛЬКО Тимлид)
1. Сделайте Fork официального репозитория.
2. Клонируйте его себе на компьютер:
   ```bash
   git clone https://github.com/[ВАШ_АККАУНТ]/html-lesson4.git
   cd html-lesson4
   ```
3. Сразу создайте рабочую ветку команды и переключитесь на неё:
   ```bash
   git checkout -b homework-04
   ```
4. В настройках вашего форка на GitHub (**Settings -> Collaborators**) обязательно добавьте аккаунты своих одногруппников по команде, чтобы они имели право делать `push` в эту ветку.

### Шаг 2. Ежедневный рабочий процесс (Для всей команды)
Перед тем как открыть редактор VS Code и начать писать код, каждый участник команды (включая Тимлида) обязан выполнить в терминале две команды:
```bash
git checkout homework-04
git pull origin homework-04
```
Это скачает последние изменения, которые ваши коллеги уже успели залить на сервер, и убережет вас от конфликтов слияния.

### Шаг 3. Сдача работы (Делает Тимлид)
Когда все страницы в вашей командной папке `team-[фамилии]/` готовы и отправлены на сервер, Тимлид заходит на страницу оригинального репозитория `fufaev/html-lesson4` на GitHub и нажимает кнопку **New Pull Request**, указывая в качестве источника ветку `homework-04` своего форка.
